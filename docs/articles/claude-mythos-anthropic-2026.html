1. Как Mythos рассекретила себя сама

Идентификатор модели просочился через публичные версии Claude Code: пользователи обнаружили упоминания claude-mythos в ответах и метаданных инструмента ещё до каких-либо официальных коммуникаций от Anthropic. Это классический leak через SDK — Claude Code при определённых запросах возвращал model ID из своего внутреннего контекста, включая идентификаторы моделей, к которым у него был доступ на бэкенде.

Anthropic не опровергла утечку. Компания подтвердила существование модели и партнёрскую программу Project Glasswing, но без технических деталей архитектуры. Отсутствие опровержения красноречивее любого пресс-релиза.

Сценарий знаком по истории GPT-4 и Gemini Ultra: модели с ограниченным доступом неизбежно оставляют следы в публичных инструментах. Разница в том, что Mythos — не просто следующая версия в линейке. Разрыв с предыдущими моделями по ключевым метрикам настолько велик, что требует отдельного объяснения.

2. Бенчмарки: что означает 93.9% на SWE-bench

93.9% на SWE-bench Verified — это не очередной рекорд таблицы лидеров. Это граница, после которой модель перестаёт быть ассистентом и становится автономным агентом разработки.

SWE-bench Verified содержит реальные GitHub issues из популярных Python-репозиториев: Django, Flask, scikit-learn, sympy. Задача модели — самостоятельно написать патч, который проходит существующий тестовый набор. Никаких подсказок, никаких вариантов ответа — только патч или провал. Evaluation pipeline изолирован: модель не имеет доступа к тестам заранее.

97.6% на USAMO — это не школьная алгебра. Задачи US Mathematical Olympiad требуют многошаговых доказательств с полным обоснованием каждого перехода, где одна ошибка в середине рассуждения обнуляет всё решение. Высокий результат здесь коррелирует с качеством многошагового планирования — именно тем, что критично для автономных агентных задач в разработке.

Что стоит за 73% в кибербезопасности

Оценка UK AI Security Institute по 73% expert-level challenges требует расшифровки. «Expert-level» в терминологии UKASI — задачи, которые профессиональный пентестер решает за несколько часов при наличии специализированной экспертизы.

Данные по Firefox exploits дают конкретный масштаб: 181 рабочий exploit из 250 попыток. Opus 4.6 в аналогичных условиях — 2 из сотен. Это не линейный прирост качества, а качественный переход в другой класс инструментов.

Автономный поиск уязвимостей — отдельный кейс. Баг в OpenBSD существовал 27 лет и прошёл мимо тысяч code review. Баг в FFmpeg возрастом 16 лет не обнаружили 5 миллионов автоматических сканирований. CVE-2026-4747 (FreeBSD NFS RCE) модель нашла полностью автономно. Это другой класс анализа: не сопоставление с базой известных паттернов, а семантическое понимание контекста исполнения и инвариантов системы.

3. Почему Anthropic не выпустила модель публично

Anthropic не выпустила Mythos публично из-за прямых свидетельств злоупотреблений на стадии закрытого тестирования — не из-за гипотетических рисков.

Кейс с мексиканским водопроводом (2025–2026) стал отправной точкой. Атакующие использовали Mythos для атаки на систему водоснабжения: задачи, требовавшие ранее недель работы специалиста по ICS/SCADA, были выполнены за часы. Это первый подтверждённый случай, когда конкретная языковая модель напрямую атрибутирована к инциденту с критической инфраструктурой.

UK AI Security Institute провёл контролируемую симуляцию: 32-шаговый network breach — полная цепочка от разведки до латерального перемещения и закрепления в сети. Mythos завершила сценарий в 3 из 10 попыток. Junior-пентестер на аналогичной задаче тратит несколько дней при постоянном supervision.

Ключевая проблема не в том, что «модель умеет взламывать». Проблема в снижении порога входа: Mythos опускает необходимый уровень экспертизы атакующего с «специалист с 5+ годами опыта» до «человек, умеющий формулировать задачи». Это структурное изменение профиля угрозы, а не просто новый инструмент.

Anthropic публично признала трейдоф: модель слишком полезна для легитимных задач (автономная разработка, security-исследования, научная работа), чтобы её заморозить. Но достаточно опасна, чтобы не выпускать без контроля. Glasswing — это управляемый эксперимент, а не маркетинговая программа.

4. Project Glasswing: кто получил доступ и зачем

Project Glasswing — структурированная программа контролируемого доступа с бюджетом $100M кредитов и $4M грантов. Не открытый бета-тест, а выверенный список организаций с конкретными use case.

Среди 12 основных партнёров: AWS, Apple, Broadcom, Cisco, CrowdStrike, Google, JPMorganChase, Linux Foundation, Microsoft, NVIDIA, Palo Alto Networks. Плюс 40 организаций расширенного круга. Итого — 52 точки контролируемого развёртывания.

Профиль партнёров объясняет логику программы по трём группам:

Инфраструктурные вендоры (AWS, Microsoft, Google) оценивают импакт модели на свои платформы до публичного релиза. Это одновременно подготовка к интеграции и аудит рисков в их собственных средах.

Компании кибербезопасности (CrowdStrike, Palo Alto Networks, Cisco) — явный стратегический приоритет. Если модель способна автономно находить 27-летние баги, она должна оказаться на стороне защиты раньше, чем доберётся до атакующих без ограничений. Glasswing создаёт асимметрию в пользу defenders.

Финансовый и открытый секторы (JPMorganChase, Linux Foundation) обеспечивают тестирование в регулируемых средах с чётко определёнными compliance-требованиями — именно те условия, в которых большинство enterprise-клиентов будут разворачивать модель.

Июль 2026 — дата полного отчёта Glasswing и раскрытия трёх CVE под embargo. CVE-2026-4747 (FreeBSD NFS RCE) Anthropic уже частично раскрыла: первый задокументированный случай, когда LLM полностью автономно обнаружила и классифицировала уязвимость в production-кодовой базе.

5. Что это значит для разработчиков прямо сейчас

Практический ответ для большинства: публичного доступа к Mythos нет, рабочий стек — Opus 4.7 и Sonnet 4.6. Но архитектура использования меняется уже сейчас, и закладывать её нужно сегодня.

Если вы строите агентные пайплайны — выносите model ID в конфигурацию. Когда Mythos выйдет в GA или выйдет промежуточная модель с частью её возможностей, смена одной строки не должна ломать пайплайн.

import anthropic

# Конфигурация модели вынесена отдельно —
# при смене меняется только MODEL_CONFIG["active"]
MODEL_CONFIG = {
    "ga":      "claude-opus-4-7-20260101",    # текущий GA, предсказуемое поведение
    "preview": "claude-mythos-20260407",       # limited preview, нужен партнёрский доступ
    "active":  "claude-opus-4-7-20260101",     # используем GA до получения доступа
}

client = anthropic.Anthropic()


def run_swe_task(repo_path: str, issue_description: str) -> str:
    """
    Агентная задача: анализ issue и генерация патча.
    На Opus 4.7 покрывает ~72% задач SWE-bench — достаточно для большинства
    стандартных issue. На Mythos — ожидаем 93.9%. Интерфейс не меняется.
    """
    response = client.messages.create(
        model=MODEL_CONFIG["active"],
        max_tokens=8192,
        system=(
            "Ты — автономный агент разработки. "
            "Анализируй code context, находи root cause проблемы, "
            "генерируй минимальный патч с покрывающими тестами. "
            "Не объясняй — пиши код."
        ),
        messages=[
            {
                "role": "user",
                "content": (
                    f"Репозиторий: {repo_path}\n\n"
                    f"Issue:\n{issue_description}\n\n"
                    "Сгенерируй patch-файл в формате unified diff."
                )
            }
        ],
    )
    return response.content[0].text


def audit_security(code_context: str) -> dict:
    """
    Аудит безопасности кодовой базы.
    С Mythos — качественно другой результат (CVE-класс находок).
    Структура ответа одинакова — закладываем уже сейчас.
    """
    response = client.messages.create(
        model=MODEL_CONFIG["active"],
        max_tokens=4096,
        messages=[
            {
                "role": "user",
                "content": (
                    "Проведи аудит безопасности кода. "
                    "Ищи не только известные CWE-паттерны, "
                    "но и семантические проблемы в логике исполнения "
                    "и нарушения инвариантов состояния.\n\n"
                    f"{code_context}"
                )
            }
        ],
    )

    return {
        "model":        MODEL_CONFIG["active"],
        "findings":     response.content[0].text,
        "tokens_total": response.usage.input_tokens + response.usage.output_tokens,
    }

Два конкретных изменения в рабочем процессе, актуальных прямо сейчас:

Делегируйте Opus 4.7 полные задачи, а не фрагменты. 72.5% на SWE-bench означает, что модель закрывает большинство стандартных задач: рефакторинг с сохранением поведения, написание unit-тестов по спецификации, дебаггинг с полным стектрейсом. Давайте ей issue целиком с приёмочными критериями — не «помоги написать функцию», а «реши задачу и покрой тестами».

Начните собирать eval-сюиту под ваш домен. Синтетические бенчмарки говорят об общем качестве, но не о том, что именно изменится в вашем конкретном коде. Когда Mythos или следующая публичная модель появится в GA, готовый набор evaluation-кейсов позволит измерить реальный прирост за часы, а не недели.

6. Когда ждать публичного доступа

Конкретной даты GA нет — Anthropic не называла сроков публично, и по структуре Glasswing это не случайность.

Ближайшая опорная точка — июль 2026: полный отчёт Glasswing, раскрытие трёх CVE под embargo, и вероятное обновление условий доступа. Это не анонс GA, но публичная оценка результатов контролируемого развёртывания — первый сигнал о том, в какую сторону движется программа.

Исходя из структуры партнёрской программы, реалистичны три сценария:

Тиерный доступ — сначала корпоративные клиенты с подтверждённым use case и compliance-окружением, затем расширение. Прецедент: GPT-4 появился сначала в Azure OpenAI Service для enterprise, позже — в ChatGPT.

Capability-флаги — модель выходит в GA с отключёнными по умолчанию функциями (автономный security audit, exploit analysis), которые включаются через отдельный approval process. Это позволяет сделать модель доступной для разработки, сохранив контроль над критическими возможностями.

Разделение линеек — Mythos остаётся закрытой моделью для партнёров, а публичная линейка получает часть возможностей через следующий Opus. Часть research-моделей Anthropic шла именно по этому пути.

Для практического планирования: если вы строите продукт на автономной разработке или security-анализе, закладывайте готовность к интеграции в горизонте Q4 2026. Если use case — стандартная разработка без специфических security-требований, Opus 4.7 покрывает 80%+ задач уже сегодня при зрелом API и предсказуемом поведении.

Три CVE под embargo — маркер, на который стоит ориентироваться. Их disclosure в июле покажет, насколько глубоко модель работает с production-кодовыми базами крупных проектов. Это будет значимее любого пресс-релиза о GA.
