Блок 4. Claude Mythos vs. конкуренты: что говорит SWE-bench

Claude Mythos опережает ближайший аналог на 21,9 процентных пункта по SWE-bench Verified — отраслевому бенчмарку, который тестирует способность ИИ-агента для кодирования решать реальные GitHub-issues в продакшн-репозиториях без подсказок и шаблонных подсказок.

На момент публикации таблица сравнения языковых моделей выглядит так:

Модель SWE-bench Verified Дата
Claude Mythos 93,9% 2026
Claude Opus 4 ~72% 2025
GPT-4o ~38% 2025
Gemini 2.0 Pro ~41% 2025
DeepSeek-R2 ~55% 2025

Разрыв между 72% и 93,9% — не эволюция, а смена класса задач в автоматизации разработки. Нейросети до 70% справляются с изолированными багфиксами. Агентные модели выше 85% начинают закрывать issue с зависимостями, side-эффектами и требованиями к рефакторингу кода — то, что раньше требовало senior-разработчика на 2–4 часа.

Ключевое отличие SWE-bench от синтетических тестов: бенчмарк не проверяет «написать функцию по описанию». Он проверяет полный инженерный цикл — прочитать issue, найти корневую причину в кодовой базе, написать патч, пройти существующие регрессионные тесты. Именно поэтому 93,9% — не маркетинговая цифра, а измеримый показатель готовности к продакшн-задачам.

Блок 5. Доступ разработчиков: что известно об API

Доступ к Claude Mythos API сейчас возможен только через waitlist и партнёрские соглашения с Anthropic — публичного GA-релиза у модели нет.

Что подтверждено из официальных источников и партнёрских каналов:

  • Вызов через api.anthropic.com с идентификатором модели вида claude-mythos-20260X-XX
  • Поддержка extended thinking с увеличенным бюджетом токенов — ключевая функция для агентного кодирования и многошаговых задач
  • Контекстное окно: предположительно 500K токенов (официально не подтверждено)
  • Tool use и computer use поддерживаются в полном объёме

Минимальный рабочий запрос через Python SDK (Anthropic SDK):

import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-mythos-20260X-XX",  # уточняйте актуальный ID модели
    max_tokens=16000,
    thinking={
        "type": "enabled",
        "budget_tokens": 10000
    },
    messages=[{
        "role": "user",
        "content": "Fix the failing test in src/auth/token.py based on the attached traceback."
    }]
)

Ценообразование на этапе ограниченного доступа: официального прайса Anthropic не публиковал. По данным партнёров — ориентир x3–x5 к стоимости Claude Opus 4. Для продакшн-пайплайнов это делает prompt caching обязательным условием: кэширование системных промптов и контекста кодовой базы снижает стоимость повторных запросов на 60–80%, иначе стоимость итерации на крупных монорепозиториях выходит за пределы ROI.

Для подачи заявки: console.anthropic.com → Early Access → Research Preview.

Блок 6. Что делать прямо сейчас

Чтобы получить и эффективно использовать Claude Mythos раньше конкурентов, команде разработки нужно выполнить три конкретных действия — и два из них не требуют доступа к модели.

1. Подайте заявку на ранний доступ сегодня. Anthropic отдаёт приоритет командам с конкретным production use-case. В форме укажите: объём кодовой базы, тип задач (автоматический bug triage, AI code review, автогенерация тестов), текущий инструментарий. Общие заявки без контекста идут в конец очереди.

2. Перейдите на Claude Opus 4 / Sonnet 4.5 с extended thinking прямо сейчас. Архитектура запросов для ИИ-агента Mythos идентична существующим моделям — те же extended thinking, tool use, structured outputs. Команда, которая уже работает с этим стеком для автоматизации разработки, получит доступ к Mythos и начнёт продуктивно использовать его в первый день без переобучения.

3. Настройте prompt caching на существующих пайплайнах. При переходе стоимость токенов вырастет кратно. Кэширование системных промптов и контекста кодовой базы — это не оптимизация «на потом», а условие рентабельности крупных языковых моделей в продакшне.

Нейросеть с 93,9% на SWE-bench не автоматизирует разработчика — она убирает latency между «понять проблему» и «написать патч». Команды, которые встроят агентное кодирование в review-цикл сейчас, получат не инструмент, а структурное ускорение разработки.
