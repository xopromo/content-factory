# Content Factory — CLAUDE.md
> Файл маршрутизации контекста и правил поведения роя агентов.
> Все субагенты обязаны прочитать этот файл перед началом работы.

## ОБЯЗАТЕЛЬНО ЧИТАТЬ ПРИ СТАРТЕ КАЖДОЙ СЕССИИ

1. `CLAUDE.md` (этот файл)
2. `PROJECT_STATE.md` — текущий статус проекта, приоритеты, нюансы реализации
3. `ai-clone/rules.md` — голос и стиль автора
4. `ai-clone/feedback/*.md` — жёсткие ограничения из прошлых ошибок (**включая `learning_rules.md`**)

Читать без напоминания пользователя. Это базовый контекст для любой работы.

## КОМАНДА «ЗАПОМНИ ЭТО»

Когда пользователь пишет «запомни это» — немедленно:
1. Определить что именно обсуждалось и какое решение принято
2. Дописать это в `PROJECT_STATE.md` в нужный раздел
3. **Запустить `scripts/feedback_learner.py` с текстом обратной связи** (если это коррекция)
4. Закоммитить: `git commit -m "memory: [краткое описание]"`
5. Подтвердить пользователю что сохранено и где именно

Это приоритет — выполнить до любых других действий в этом сообщении.

## ОБЯЗАТЕЛЬНО ОБНОВЛЯТЬ PROJECT_STATE.md

После каждого значимого действия обновить `PROJECT_STATE.md`:
- Задача выполнена → отметить статус, убрать из приоритетов
- Принято архитектурное решение → зафиксировать с обоснованием
- Появился новый нюанс или ограничение → добавить в раздел «Важные детали»
- Изменились переменные окружения или зависимости → обновить соответствующий раздел
- **Добавлена новая функциональность (например, обучение на обратной связи) → подробно описать в новом разделе**

Обновление `PROJECT_STATE.md` — часть каждого коммита, не отдельный шаг.

## 5. Маршрутизация контекста для субагентов

Каждый субагент при старте ОБЯЗАН:

1. **Прочитать этот файл** (`CLAUDE.md`)
2. **Прочитать `ai-clone/rules.md`** — правила голоса и стиля
3. **Агрегировать `ai-clone/feedback/*.md`** — список жестких ограничений из прошлых ошибок (**включая `learning_rules.md`**)
4. **Получить задачу от оркестратора** из соответствующего файла в `plans/`

### Контекст по ролям (обновлено 2026-06-22):

| Субагент            | Дополнительно читает                                                                 | Новые обязанности                                                                                     |
|---------------------|--------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------|
| `lead-orchestrator` | `plans/`, `retrospectives/` (последние 3)                                           | Запускает `feedback_learner.py` при получении обратной связи от пользователя                          |
| `knowledge-retriever`| `knowledge/` (поиск через `scripts/knowledge_search.py`)                             | Ищет структурированную обратную связь в `knowledge/feedback_*.md` для контекста                      |
| `content-writer`    | пакет от `knowledge-retriever` + `business/`                                        | Применяет правила из `learning_rules.md` для автокоррекции текста                                     |
| `entity-validator`  | источники + `ai-clone/feedback/learning_rules.md`                                   | Проверяет текст на соответствие правилам с severity=CRITICAL (блокирует при нарушениях)               |
| `editor-critic`     | весь контент + `ai-clone/feedback/learning_rules.md`                                | Учитывает WARNING-правила при финальном аудите                                                        |

## 6. Интеграция обучения на обратной связи

### Правила для субагентов:
1. **При получении команды «Запомни это»**:
   - `lead-orchestrator` немедленно запускает `scripts/feedback_learner.py` с текстом обратной связи.
   - Пример: `python scripts/feedback_learner.py "Запомни: Devika — ошибка, правильно Devin"`

2. **При генерации контента**:
   - `content-writer` проверяет текст на соответствие правилам из `learning_rules.md` (severity=CRITICAL/WARNING).
   - Пример: Если в правилах есть триггер "Devika", заменяет на "Devin" и логирует предупреждение.

3. **При валидации сущностей**:
   - `entity-validator` блокирует статью, если находит сущности с severity=CRITICAL в `learning_rules.md`.
   - Пример: Обнаружено "Devika" → блокировка с сообщением "Нарушено правило lr-001: заменить на 'Devin'".

4. **После публикации**:
   - `deployer-publisher` запускает `feedback_learner.py` для обработки комментариев/правок пользователя (если есть).

### Пример работы системы:
```
Пользователь: "Запомни это: Devika — это ошибка, правильно Devin"
→ lead-orchestrator запускает feedback_learner.py
→ Создаётся правило в learning_rules.md:
   {"trigger": "Devika|Devica", "action": "Заменить на 'Devin'", "severity": "CRITICAL"}
→ content-writer при следующей генерации автоматически заменяет "Devika" на "Devin"
→ entity-validator блокирует статью, если находит "Devika"
```
