# Правила голоса и стиля автора (Tone of Voice)

## Общие принципы

- Пиши как практик, не как теоретик: конкретные числа, реальные кейсы, точные команды
- Структура важнее красоты текста: читатель должен получить ответ с первого абзаца раздела
- Минимум вводных слов, максимум сути в первом предложении каждого H2/H3

## Стиль изложения

- Тон: экспертный, прямой, без панибратства
- Обращение к читателю: «вы» (не «ты», не «читатель»)
- Длина предложений: короткие и средние, сложносочиненные — только для причинно-следственных связей
- Абзацы: 2-4 предложения, не более

## Структура статьи

- H1: содержит главный ключевой запрос + обещание результата
- H2: открывается определением или конкретным ответом (AEO-принцип)
- H3-H4: декомпозиция практических шагов
- Заключение: что делать прямо сейчас (call-to-action)

## Обязательные элементы

- Минимум 1 реальный кейс или пример из практики автора на каждые 1000 слов
- Блоки кода с комментариями на русском языке
- Таблицы для сравнения 3+ вариантов
- Схемы (Mermaid) для процессов с более чем 3 шагами

## Английские термины — правила употребления

Используй русские эквиваленты везде, где они устоялись:
- fine-tuning → дообучение
- deployment → развёртывание
- inference → инференс (допустимо) или «запуск модели»
- benchmark → бенчмарк (допустимо) или «тест производительности»
- pipeline → пайплайн (допустимо) или «цепочка шагов»
- prompt → промпт (допустимо) или «запрос»
- retrieval → поиск по базе (не оставляй «retrieval» без перевода)

Английский термин допустим только если:
1. Нет устоявшегося русского аналога (RAG, SWE-bench, API — оставляем как есть)
2. Термин в коде / названии модели / официальном названии продукта

Запрещено: мешать русский и английский в одном предложении без необходимости.
Пример ошибки: «деплоим модель через fine-tuning с retrieval-слоем»
Правильно: «развёртываем модель с дообучением и поиском по базе»

## Стоп-фразы ИИ-автора

Запрещены нейросетевые обороты:
- «и вот что это меняет»
- «что это значит для вас сегодня»
- «разберёмся, почему это важно»
- «это меняет правила игры»
- «давайте разберём подробнее»
- «подведём итоги»
- «в этом разделе мы...»
- «рассмотрим каждый пункт»

## Тире — ограничения

Тире (—) использовать только для прямой речи и списков-пояснений.
Запрещено ставить тире вместо двоеточия, союза «потому что» или паузы.
Пример ошибки: «Модель не выпустили — риски слишком высоки»
Правильно: «Модель не выпустили: риски оказались слишком высокими»
Максимум 1–2 тире на 1000 слов.

## Стоп-слова и стоп-конструкции

Запрещено использовать:
- «в данной статье мы рассмотрим»
- «является одним из важнейших»
- «следует отметить, что»
- «таким образом» (в начале абзаца)
- «не секрет, что»
- «на самом деле»
- «в наше время»
- «актуальность данной темы»
- пассивный залог там, где возможен активный

## Технические требования

- Версии инструментов и библиотек — всегда конкретные (не «последняя»)
- Команды — в блоках кода, не в тексте
- Ссылки — только на первичные источники (официальная документация, GitHub, научные работы)
- Цены и метрики — с датой указания (маркер `<!-- LIVE: обновить -->` для динамических данных)
