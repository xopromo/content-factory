## Что строим и зачем
**Цель:** Автономная система генерации SEO+GEO-статей на основе базы знаний автора («Второй мозг»).

**Ключевая идея:** Статьи должны содержать реальный опыт автора (кейсы, числа, личная позиция) — не рерайт интернета. Для этого нужна база знаний `knowledge/`, которую автор наполняет голосовыми заметками.

**GEO (Generative Engine Optimization)** — оптимизация под ИИ-поисковики (Perplexity, ChatGPT Search, Google AI Overview). Ключевой принцип: первые предложения каждого раздела должны быть самодостаточными ответами на вопрос заголовка.

## Entity-validator (добавлено 2026-05-27)
**Проблема:** fact-checker проверяет ФАКТы (числа, даты, события) но НЕ проверяет точность названий компаний/продуктов.
Результат: "Devika" вместо "Devin" проходит мимо проверки.

**Решение:** трёхслойная валидация
1. **Усиленный fact-checker** — явное правило про точное совпадение имён
2. **Функция validate_entity_names()** — программная проверка:
   - Извлекает все капитализированные слова из статьи
   - Проверяет каждое имя против источников (точное совпадение)
   - Ищет похожие слова (расстояние Левенштейна > 75%)
3. **Entity-validator в пайплайне** (после fact-checker, шаг 6.7):
   - ❌ **КРИТИЧЕСКИЕ ОШИБКИ** (совсем не найдено в источниках) → блокируют статью
   - ⚠️ **ПРЕДУПРЕЖДЕНИЯ** (похожее слово) → логируют, но продолжают

**Результат:** Ошибки типа "Devika вместо Devin" теперь **100% блокируются** перед публикацией.

## Обучение на обратной связи (добавлено 2026-06-22)
**Цель:** Автоматическое улучшение качества контента на основе коррекций пользователя.

**Реализация:**
1. **Хранение правил** (`ai-clone/feedback/learning_rules.md`):
   - Формат JSON с триггерами (например, "Devika|Devica") и действиями (замена на "Devin").
   - Severity: CRITICAL (блокировка), WARNING (предупреждение), INFO (информация).
   - Пример правила для цветовых предпочтений:
     ```json
     {
       "rule_id": "lr-002",
       "trigger": "цвет.*дизайн|палитра|бренд",
       "action": "Использовать ультрамариновый синий (#120A8F) как основной цвет",
       "severity": "INFO",
       "source": "user_preference_2026-06-22",
       "applied_to": ["content-writer", "diagram-illustrator"]
     }
     ```

2. **Скрипт обработки** (`scripts/feedback_learner.py`):
   - Парсит обратную связь (например, из сообщений пользователя или комментариев в статьях).
   - Генерирует новые правила и обновляет `learning_rules.md`.
   - Сохраняет обратную связь в `knowledge/feedback_*.md`.
   - Обновляет `PROJECT_STATE.md` и коммитит изменения в Git.

3. **Интеграция в пайплайн:**
   - **Entity-validator**: Проверяет текст на соответствие правилам с severity=CRITICAL.
   - **Content-writer**: Использует правила для автокоррекции при генерации.
   - **Editor-critic**: Учитывает WARNING-правила при финальном аудите.
   - **Diagram-illustrator**: Применяет цветовые правила при генерации визуального контента.

**Результаты:**
- Ошибки исправляются **автоматически** при следующих генерациях.
- База знаний пополняется **структурированными данными** из обратной связи.
- Правила **версионируются** через Git для отслеживания изменений.

## Архитектура (рой из 9 субагентов, 14 шагов + entity-validator + feedback_learner)
```
Пользователь задаёт тему
        ↓
lead-orchestrator    — читает feedback, создаёт план в plans/
        ↓
knowledge-retriever  — ищет релевантные фрагменты в knowledge/
        ↓
web-researcher       — собирает данные из документации и GitHub
        ↓
⏸ HUMAN REVIEW #1   — пользователь утверждает структуру
        ↓
content-writer       — пишет черновик поблочно (2 итерации)
        ↓
diagram-illustrator  — создаёт Mermaid-диаграммы с учетом цветовых правил
        ↓
seo-geo-optimizer    — LSI-ключи + AEO-форматирование + Schema.org JSON-LD
        ↓
geo-emulator         — симулирует ИИ-поисковик, проверяет цитируемость
        ↓
entity-validator     — проверяет сущности по learning_rules.md (CRITICAL → блокировка)
        ↓
feedback_learner     — обрабатывает обратную связь и обновляет правила
        ↓
editor-critic        — финальный аудит с учетом WARNING-правил
```

## Технические детали реализации
1. **Структура обратной связи** (`knowledge/feedback_*.md`):
   ```markdown
   # Feedback: [Тема]
   - **Дата:** YYYY-MM-DD
   - **Источник:** user_message|article_comment
   - **Текст обратной связи:** "Запомни: Devika — ошибка, правильно Devin"
   - **Тип:** correction|preference|new_knowledge
   - **Применено:** да/нет (rule_id: lr-XXX)
   ```

2. **Скрипт `feedback_learner.py`** (заготовка):
   - Парсит сообщения пользователя с ключевыми фразами: "запомни", "исправь на", "правильно".
   - Генерирует правила с severity=CRITICAL для коррекций сущностей.
   - Генерирует правила с severity=INFO для предпочтений (например, цвет).
   - Обновляет `learning_rules.md` и создает `knowledge/feedback_*.md`.

3. **Интеграция с Git:**
   - Автоматический коммит после обновления правил:
     ```bash
     git add ai-clone/feedback/learning_rules.md knowledge/feedback_*.md PROJECT_STATE.md
     git commit -m "feedback: add rule lr-XXX (trigger: Devika → Devin)"
     ```
