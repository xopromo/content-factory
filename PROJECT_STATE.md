## Что строим и зачем

**Цель:** Автономная система генерации SEO+GEO-статей на основе базы знаний автора («Второй мозг»).

**Ключевая идея:** Статьи должны содержать реальный опыт автора (кейсы, числа, личная позиция) — не рерайт интернета. Для этого нужна база знаний `knowledge/`, которую автор наполняет голосовыми заметками.

**GEO (Generative Engine Optimization)** — оптимизация под ИИ-поисковики (Perplexity, ChatGPT Search, Google AI Overview). Ключевой принцип: первые предложения каждого раздела должны быть самодостаточными ответами на вопрос заголовка.

## Архитектура (рой из 9 субагентов, 14 шагов)

```
Пользователь задаёт тему
        ↓
lead-orchestrator    — читает feedback, создаёт план в plans/
        ↓
knowledge-retriever  — ищет релевантные фрагменты в knowledge/
        ↓
web-researcher       — собирает данные из документации и GitHub
        ↓
⏸ HUMAN REVIEW #1   — пользователь утверждает структуру
        ↓
content-writer       — пишет черновик поблочно (2 итерации)
        ↓
diagram-illustrator  — создаёт Mermaid-диаграммы
        ↓
seo-geo-optimizer    — LSI-ключи + AEO-форматирование + Schema.org JSON-LD
        ↓
geo-emulator         — симулирует ИИ-поисковик, проверяет цитируемость
        ↓
editor-critic        — финальный аудит качества (5 критериев)
        ↓
⏸ HUMAN REVIEW #2   — пользователь утверждает статью
        ↓
deployer-publisher   — коммит в git, публикация в docs/articles/
```

- Regex: `\*\*(.*?)\*\*` → `\1`

✅ **Mandatory content-writer CHECKLIST**: 6 пунктов проверки перед отправкой
- КТО/ЧТО/КОГДА/ПОЧЕМУ в первом предложении лида
- Нет служебных оборотов ("Это показывает", "Это значит", "Следует отметить")

- H2 не чаще чем через 2-3 абзаца (макс 2-3 H2 на весь текст)
- Нет жирного текста внутри предложений

## Голосовой бот (voice_bot.py)

**Зачем:** самый быстрый способ наполнять `knowledge/` — наговорить голосовое в Telegram.

**Как работает:**
1. Отправляешь голосовое боту в Telegram
2. Groq Whisper транскрибирует (~5 сек на минуту речи)
3. Бот показывает транскрипт и предлагает выбрать категорию
4. Файл сохраняется в `knowledge/voice/YYYY-MM-DD_HH-MM_категория.md`

**Категории заметок:**
- 💼 Кейс — реальный результат с числами
- 💡 Инсайт — паттерн, открытие
- 📋 Гайд — пошаговая инструкция
- 🎯 Стратегия — рассуждения о подходе
- ❓ Гипотеза — идея для проверки
- 📝 Просто мысль — всё остальное

**Переменные окружения (в .env):**
```
TG_BOT_TOKEN=   # от @BotFather в Telegram
TG_CHAT_ID=     # свой id от @userinfobot
GROQ_KEY=       # от console.groq.com (бесплатно, ключи уже есть)
```

**Запуск:**
```bash
python3 scripts/voice_bot.py
```

**Где хостить:**
- **Render.com** (бесплатно, без карты) — worker service, работает 24/7
- Файлы сохраняются не на диск сервера, а прямо в GitHub репозиторий через GitHub API
- Нужен дополнительный ключ: `GITHUB_TOKEN` (Personal Access Token, права `contents:write`)
- Конфиг деплоя: `render.yaml` в корне репо

**Как задеплоить на Render:**
1. render.com → New → Blueprint → подключить репо xopromo/content-factory
2. Render найдёт `render.yaml` автоматически
3. В Environment Variables добавить: TG_BOT_TOKEN, GROQ_KEY, TG_CHAT_ID, GITHUB_TOKEN
4. Deploy — бот онлайн

**Как получить GITHUB_TOKEN:**
GitHub → Settings → Developer settings → Personal access tokens → Fine-grained
Права: Repository → xopromo/content-factory → Contents: Read and Write

## Правила написания статей (выводы из редактирования)

**Записано:** 2026-05-27 после переписи статьи про Карпатого

### Структура и заголовки

- **H2 не чаще чем через 2-3 абзаца**: минимум 2 полнотекстовых абзаца под заголовком
- **Заголовок = конкретный тезис**, не абстрактный. ✅ "Усиление Anthropic меняет баланс сил", ❌ "Новая фаза гонки ИИ"
- **Порядок смысла**: действие (что случилось) → контекст (почему это важно) → следствие (что это означает)

### Убирать служебные обороты

Эти фразы замедляют текст и не несут информации (читатель помнит контекст):
- "Это показывает, что..." → удалить, начать со смысла
- "Присоединившись к..." → удалить если не даёт новой информации
- "Переход X показывает..." → заменить на прямое утверждение
- "стал значительным успехом для" → "укрепил позиции"

**Правило:** каждое предложение должно добавлять новый факт или смысл. Если предложение только переформулирует предыдущее — убирать.

### Лид (первое предложение статьи)

- **Начинать с ДЕЙСТВИЯ, не с персоны**: ✅ "Anthropic усилила команду инженером X", ❌ "Инженер X перешёл в Anthropic"
- **Контекст — ВО ВВОДЕ**: почему это важно, с кем конкурирует, какая борьба (в одном предложении)
- **Избегать списков должностей** — вместо "сооснователь OpenAI, бывший директор Tesla" писать: "человек, который создавал автопилот в Tesla и стоял у истоков OpenAI"

### Детали вместо штампов

Одна конкретная деталь > трёх штамповых фраз:
- ❌ "известный специалист в области глубокого обучения"
- ✅ "автор бесплатного YouTube-курса Neural Networks: Zero to Hero, набравшего миллионы просмотров"

- ❌ "работал над ключевыми проектами в Tesla"
- ✅ "создавал автопилот в Tesla"

- ❌ "масштабировал обучение моделей"
- ✅ "руководил исследованиями в OpenAI"

**Правило:** если упоминаешь источник или опыт — уточнять масштаб и конкретность.

### Вывод статьи

- **НЕ суммировать** сказанное в статье
- **Дать новый ракурс или инсайт**: переформулировать проблему, показать скрытое следствие
- **Показать долгосрочное последствие**: что это значит не сейчас, а потом

Пример хорошего вывода: "главным дефицитом в ИИ-гонке становятся не чипы и дата-центры, а штучные специалисты, способные координировать обучение гигантских систем" — это не резюме, это новая мысль.

### Про Суgarman и copywriting

**Использовать ТОЧЕЧНО для новостей о технологии:**
- ✅ Убирать повторы имён
- ✅ Добавлять конкретные детали
- ✅ Писать короче, плотнее
- ❌ Метафоры и образные сравнения
- ❌ Философские отступления
- ❌ "Продажные" фразы ("это меняет правила игры", "перейди на новый уровень")

**Баланс:** структурированность + живость, но без литературных приёмов. Это новость, не реклама.

### Специфика режима NEWS (добавлено 2026-05-27)

Для новостного режима (`--mode news`) дополнительные ограничения:

- **Объём: максимум 600 слов**. Если получается больше — переделай как аналитику в режим SEO/FULL
- **Максимум 2 H2-заголовка**. Если логически требуется больше — объединяй в абзацы внутри одного раздела
- **Структура:** ЧТО произошло (лид) → КАК/ПОЧЕМУ (детали, 1-2 абзаца) → ЗНАЧЕНИЕ (смысл/вывод, 1 абзац)
- **Лид содержит ВСЕ ключевые факты** в первом предложении: ТО КТО, ЧТО, КОГДА, ПОЧЕМУ
  - ❌ "Компания запустила новую услугу" (где? для кого? зачем?)
  - ✅ "Anthropic запустила Claude для работы с видео на Android" (кто, что, где, для чего)
- **Убирай ВСЕ служебные обороты**, даже если кажутся связующими:
  - ❌ "Это важное событие показывает, что..." (вводное, замедляет)
  - ✅ "Компания запустила..." (сразу факт)

**Почему:** новость должна читаться за 2-3 минуты. Каждое слово считается.
