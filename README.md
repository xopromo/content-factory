# content-factory
Automated content search & digest factory

---

## 🌐 Деплой и Мониторинг (Keep-Alive)

Для работы Telegram-бота и автоматического сбора прокси на бесплатном тарифе **Render.com** настроены следующие параметры:

### 1. Веб-сервис (Бот)
* **Хостинг**: [Render.com](https://render.com)
* **Адрес бота (Root URL)**: `https://voice-bot-ohfb.onrender.com/`
* **GitHub Репозиторий**: `https://github.com/xopromo/content-factory`

### 2. Пинг-сервис (Удержание активности)
Чтобы бесплатный контейнер на Render не засыпал (не уходил в sleep после 15 минут простоя), используется пинг-сервис:
* **Сервис**: [UptimeRobot](https://uptimerobot.com) (или альтернатива [cron-job.org](https://cron-job.org))
* **Интервал**: каждые 5-10 минут
* **Целевой URL**: `https://voice-bot-ohfb.onrender.com/`
* **⚠️ Важное примечание по статусу**: Запрос к корневому URL возвращает ошибку **`404 Not Found`** (так как там нет веб-страницы бота, вебхук слушает по секретному пути). Это абсолютно нормально! Главное, что запрос доходит до сервера, и Render пробуждается. На UptimeRobot этот монитор может отображаться со статусом "Down" (из-за 404), но свою задачу по удержанию бота в сети он выполняет на 100%.

### 3. Автоматический сборщик прокси (Proxy Harvester)
* **Как работает**: Скрипт `scripts/proxy_harvester.py` автоматически опрашивает публичные Telegram-каналы, проверяет работоспособность прокси, отправляет живые в ваш канал и удаляет мертвые.
* **Как запущен**: Так как Cron-сервисы на Render платные, проверка запущена в фоновом цикле (background loop) прямо внутри основного веб-процесса бота с интервалом в 20 минут.
* **Переменная окружения на Render**: `TG_PROXY_CHANNEL` (указывает имя вашего канала, например `@my_clean_proxies`).
* **Ручной запуск**: В любой момент можно отправить боту команду `/harvester` для принудительного запуска проверки и очистки.
